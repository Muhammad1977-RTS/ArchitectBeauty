# ArchitectBeauty — техническая спецификация

## Обзор

ArchitectBeauty — строительный маркетплейс, который соединяет клиентов, нуждающихся в ремонте квартир и домов, с мастерами-исполнителями. Клиент создаёт заявку с типом работы и площадью, мастера откликаются с ценой и сроками, клиент выбирает подходящего исполнителя. Расчёт стоимости автоматический: площадь × ставка мастера за м² по конкретному виду работ. Запуск — Чеченская Республика, архитектура рассчитана на расширение по регионам РФ.

**Стек:** Angular (frontend) · Supabase Auth + PostgreSQL (backend) · Supabase Storage (фото) · Supabase email (уведомления)

---

## Пользовательские истории

**Клиент**
- Регистрируюсь как клиент, указываю имя, телефон, район
- Создаю заявку: выбираю тип работы, указываю площадь, адрес, описание, прикладываю фото
- Вижу список своих заявок и их статусы
- Просматриваю отклики мастеров на мою заявку — вижу предложенную цену, срок, комментарий
- Выбираю мастера — заявка переходит в статус «мастер выбран»
- Отмечаю работу завершённой

**Мастер**
- Регистрируюсь как мастер, указываю имя, телефон, специализации и ставки за м² для каждой
- Вижу все открытые заявки клиентов
- Откликаюсь на заявку: цена рассчитывается автоматически (площадь × моя ставка), могу скорректировать, добавляю комментарий и срок
- Получаю email-уведомление когда клиент выбрал меня
- Вижу список своих откликов

## Функциональность MVP

### 1. Авторизация
- Регистрация: email + пароль + выбор роли (клиент / мастер)
- Вход, выход, сброс пароля (Supabase Auth)
- После регистрации — редирект на заполнение профиля

**Критерий приёмки:** пользователь может зарегистрироваться как клиент или мастер, войти и выйти; при попытке открыть защищённый маршрут без авторизации — редирект на /auth/login

### 2. Профили
- Клиент: имя, телефон, город/район
- Мастер: имя, телефон + таблица ставок (тип работы → ₽/м²)
- Редактирование профиля в любое время

**Критерий приёмки:** мастер может добавить ставку для «укладка плитки = 800 ₽/м²» и сохранить; при создании отклика эта ставка используется в авторасчёте

### 3. Заявки (клиент)
- Создание заявки: тип работы (выбор из 12 вариантов), площадь (м²), адрес/район, описание, фото (до 5 штук, опционально)
- Список своих заявок с фильтром по статусу
- Просмотр одной заявки с откликами мастеров

**Критерий приёмки:** клиент создаёт заявку «штукатурка, 40 м², Грозный, Октябрьский район» — заявка появляется в списке со статусом «новая»

### 4. Просмотр заявок (мастер)
- Лента всех открытых заявок (статус «новая»)
- Карточка: тип работы, площадь, район, дата создания
- Детальный просмотр заявки с фото и описанием
- Нельзя откликнуться дважды на одну заявку

**Критерий приёмки:** мастер видит заявку клиента в ленте; после отклика кнопка «откликнуться» исчезает для этой заявки

### 5. Отклики мастера
- Поля отклика:
  - предлагаемая цена (авторасчёт = площадь × ставка, редактируемое поле)
  - комментарий (свободный текст)
  - срок выполнения (дней)
- Если у мастера нет ставки для данного типа работы — цена вводится вручную

**Критерий приёмки:** мастер с ставкой «штукатурка = 400 ₽/м²» откликается на заявку 40 м² — поле цены предзаполняется 16 000 ₽, мастер может изменить

### 6. Выбор мастера (клиент)
- Клиент видит все отклики на свою заявку: имя мастера, цена, срок, комментарий
- Кнопка «выбрать» напротив каждого отклика
- После выбора: статус заявки → «мастер выбран», остальные отклики заморожены
- Кнопка «завершить» переводит заявку в статус «завершена»

**Критерий приёмки:** клиент выбирает мастера → выбранный мастер получает email «вас выбрали по заявке #...» → статус заявки меняется

### 7. Email-уведомления
- Мастеру: новая заявка по его специализации *(Claude's pick — user deferred настройку; реализуем через Supabase Database Webhooks → Edge Function → Resend)*
- Клиенту: пришёл новый отклик на заявку
- Мастеру: клиент выбрал его

## Row Level Security (Supabase RLS)

| таблица | правило |
|---------|---------|
| profiles | SELECT — любой авторизованный; UPDATE — только свой профиль |
| master_rates | SELECT — любой авторизованный; INSERT/UPDATE/DELETE — только свой master_id |
| orders | SELECT(new) — любой авторизованный; INSERT — только клиент; UPDATE status — только владелец |
| responses | SELECT — владелец заявки + сам мастер; INSERT — только мастер, статус заявки = 'new' |

## Основные Supabase-запросы

```typescript
// Все открытые заявки для мастера
supabase
  .from('orders')
  .select('*, work_types(name), profiles!client_id(name, city_district)')
  .eq('status', 'new')
  .order('created_at', { ascending: false })

// Создать отклик
supabase
  .from('responses')
  .insert({ order_id, master_id, proposed_price, comment, estimated_days })

// Выбрать мастера (клиент)
supabase
  .from('orders')
  .update({ status: 'master_selected', selected_master_id: masterId })
  .eq('id', orderId)
  .eq('client_id', currentUserId)

// Авторасчёт цены на фронте
const rate = await supabase
  .from('master_rates')
  .select('rate_per_sqm')
  .eq('master_id', masterId)
  .eq('work_type_id', workTypeId)
  .single()
const price = order.area_sqm * (rate.data?.rate_per_sqm ?? 0)
```

## Пошаговый план разработки

### Этап 1 — Фундамент (auth + профили)
1. Инициализировать Angular-проект, подключить `@supabase/supabase-js`
2. Создать таблицы `profiles`, `work_types` (seed), `master_rates` в Supabase
3. Настроить RLS для всех таблиц
4. Реализовать `AuthService` (register, login, logout, getCurrentUser)
5. Страницы: /auth/register (с выбором роли), /auth/login
6. `ProfileEditComponent` — форма профиля + ставки для мастера
7. `AuthGuard` и `RoleGuard`

### Этап 2 — Заявки
1. Создать таблицу `orders`
2. `OrderCreateComponent` — форма заявки, загрузка фото в Supabase Storage
3. `ClientOrdersListComponent` — список своих заявок с фильтром по статусу
4. `ClientOrderDetailComponent` — просмотр заявки

### Этап 3 — Отклики и выбор мастера
1. Создать таблицу `responses`
2. `MasterOrdersBrowseComponent` — лента открытых заявок
3. `MasterOrderDetailComponent` — просмотр + форма отклика с авторасчётом
4. `ClientOrderDetailComponent` — список откликов, кнопка «выбрать», кнопка «завершить»
5. `MasterMyResponsesComponent` — история откликов мастера

### Этап 4 — Уведомления и шлифовка
1. Supabase Database Webhook → Edge Function → Resend (3 типа писем)
2. Применить DESIGN.md: Airbnb-стиль для клиентской части, Notion-стиль для кабинета мастера
3. Обработка ошибок, валидация форм, пустые состояния
4. Тест полного цикла: регистрация → заявка → отклик → выбор мастера → завершение

## Вне MVP (с причинами)

| фича | причина отложить |
|------|-----------------|
| Перевозчики | отдельная бизнес-модель, свои таблицы и флоу — добавим после валидации ядра |
| Строймагазины | каталог товаров — отдельный модуль, не нужен для первой сделки |
| Чат | сложность realtime + модерация; на старте хватит телефона из профиля |
| Отзывы и рейтинги | нужна история сделок — добавим после первых завершённых заказов |
| Онлайн-оплата | платёжный шлюз = юрлицо + интеграция; MVP проверяет спрос без этого |
| Панель администратора | верификация мастеров отложена; когда добавим — нужна |
| Портфолио «до/после» | важно для доверия, но не блокирует первую сделку |
| iOS / Android приложение | PWA достаточно для MVP |

## Расширение после MVP

- **Чат:** Supabase Realtime channels, один канал на пару `(order_id, master_id)` — добавляется без изменения существующих таблиц
- **Отзывы:** таблица `reviews (order_id, author_id, target_id, rating, text)` + avg_rating на профиле мастера
- **Оплата:** интеграция ЮKassa / Stripe, добавить поле `payment_status` в `orders`, эскроу-флоу отдельным этапом
- **Перевозчики:** новая роль `carrier` + таблица `transport_orders` (откуда, куда, вес, дата) — те же паттерны что и у мастеров
- **Строймагазины:** роль `shop` + таблицы `products`, `product_orders` — маркетплейс внутри маркетплейса
- **Регионы:** поле `region` в `profiles` и `orders`, фильтр по региону в ленте

## Решённые архитектурные вопросы

| вопрос | решение |
|--------|---------|
| Отмена заявки после выбора мастера | **Нет** — статус `master_selected` финальный, отменить нельзя |
| Показывать заявки мастеру без ставки | **Да, показывать** *(claude's pick)* — поле цены остаётся пустым, мастер вводит вручную; скрывать заявки означает упускать заказы |
| Публичная страница профиля мастера | **Да** *(claude's pick)* — маршрут `/master/:id`, доступен клиентам; показывает имя, специализации, район; без рейтинга до появления отзывов |

## Монетизация

MVP запускается **бесплатно** — приоритет набрать базу клиентов и мастеров, подтвердить спрос.

### Фаза 1 — после первых 50 активных мастеров
**Платные отклики (кредитная модель)**
- Мастер покупает пакет кредитов: например, 10 откликов за 500 ₽
- Каждый отклик на заявку списывает 1 кредит
- Первые 10 откликов бесплатно (онбординг)
- Доказанная модель для РФ (Профи.ру, YouDo) — мастера привыкли платить за лиды

*Что нужно добавить в БД:* поле `credits_balance` в `profiles`, таблица `credit_transactions`

---

### Фаза 2 — после подключения онлайн-оплаты
**Комиссия с транзакции — 5–8%**
- Деньги проходят через платформу (эскроу)
- Комиссия списывается при переводе мастеру
- Мотивирует обе стороны использовать платформу, а не уходить «в наличку»

---

### Фаза 3 — после добавления магазинов и перевозчиков
**Подписка для бизнес-аккаунтов**
- Строймагазины: ~3 000–10 000 ₽/мес за размещение каталога и получение заявок на материалы
- Перевозчики: ~1 000–2 000 ₽/мес за доступ к заявкам на перевозку

**Продвижение**
- Мастер / магазин платит за поднятие карточки в топ ленты
- Бейдж «Проверенный мастер» — после прохождения верификации документов (платная услуга)

**Лиды для магазинов**
- Мастер в отклике указывает нужные материалы → магазин платит за целевой лид
- Интеграция: кнопка «заказать материалы» прямо в заявке

# Мастеро — Спецификация проекта

## Стек

- **Frontend**: Angular 17+ (standalone components, signals, lazy loading)
- **Backend**: Supabase (PostgreSQL + Auth + PostgREST + Realtime)
- **Хостинг БД**: Supabase Cloud

---

## Роли пользователей

| Роль | Описание |
|---|---|
| `client` | Заказывает ремонт и перевозки |
| `master` | Берёт заказы на ремонт |
| `carrier` | Берёт заявки на перевозку грузов |
| `is_admin` | Флаг, даёт доступ к /admin панели |

---

## Функциональные модули

### Ремонт (client ↔ master)
- Клиент создаёт заказы на ремонт
- Мастер просматривает и откликается
- Клиент выбирает мастера, завершает с рейтингом

### Перевозки (client ↔ carrier)
- Клиент создаёт транспортные заявки
- Перевозчик просматривает и откликается с ценой
- Клиент выбирает перевозчика, завершает с рейтингом
- Статусы: `new → carrier_selected → completed | cancelled`

### Профили
- Мастер: специализации, описание, рейтинг
- Перевозчик: тип транспорта, цена за км, мин. цена, макс. грузоподъёмность (опционально)

### Админ-панель
- Управление пользователями, типами работ, жалобами

## Миграция с Supabase на собственный бэкенд

### Причина
Supabase недоступен без VPN в регионе пользователя. После завершения всего функционала нужен переход на собственный бэкенд.

### Когда делать
**Лучший момент**: когда все роли реализованы, функционал протестирован и проект готов к продакшену. До этого — работаем на Supabase.

### Что заменить

| Supabase | Своё решение |
|---|---|
| PostgreSQL (cloud) | PostgreSQL self-hosted (Railway, Render, VPS) |
| Supabase Auth | NestJS + Passport.js + JWT + bcrypt |
| PostgREST API | NestJS REST API |
| RLS политики | Guards / Middleware в NestJS |
| Supabase Realtime | Socket.io (WebSocket) |
| supabase-js клиент | Angular HttpClient |

### Архитектура нового бэкенда

```
NestJS API
├── auth/          — регистрация, логин, JWT refresh
├── users/         — профили, роли
├── orders/        — заказы на ремонт
├── responses/     — отклики мастеров
├── transport/     — транспортные заявки и отклики
├── carriers/      — профили перевозчиков
└── admin/         — управление пользователями
```

### Что НЕ придётся переписывать
- Все Angular компоненты и шаблоны
- Бизнес-логику в компонентах
- Роутинг и guards (только auth.guard поменяется)
- Стили и UI

### Что придётся переписывать
- `SupabaseService` → базовый `HttpClient` сервис
- `AuthService` — логин/регистрация через REST вместо supabase-js
- Все методы в сервисах (`ProfileService`, `CarrierService` и т.д.) — запросы через `HttpClient` вместо supabase-js
- База данных остаётся та же (PostgreSQL, та же схема)
